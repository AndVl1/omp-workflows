# omp-workflows

Declarative multi-stage workflow engine for [oh-my-pi](https://github.com/oh-my-pi). Native extension package — ships as a workspace of three npm packages:

- **`@omp-workflows/core`** — pure engine: state machine, gates, slash commands, profiles, artifact schemas. No agents, no skills, no domain opinions.
- **`@omp-workflows/content`** — internal source of truth for the agent + skill markdown (17 agents, 31 skills). Private workspace package; never published.
- **`@omp-workflows/fullstack`** — default bundle: ships the fullstack role/model/scope defaults, compiled `registerTeamWorkflow`. Published tarball materialises `content/{agents,skills}` via the prepack script.

Custom bundles (Rust, Go-only, minimal Python, etc.) compose core with their own role mappings.

## Install

Packages are published to **GitHub Packages** under `npm.pkg.github.com`, scope `@omp-workflows`. Add the registry to your npm config once, then install:

```bash
# One-time: authenticate to GitHub Packages.
# Use a GitHub personal access token with `read:packages` for public packages,
# or `repo` scope for private packages.
echo "@omp-workflows:registry=https://npm.pkg.github.com" >> ~/.npmrc
echo "//npm.pkg.github.com/:_authToken=ghp_xxx" >> ~/.npmrc

# Most projects: fullstack (engine + agents + skills)
npm install @omp-workflows/fullstack

# Engine-only (no agents / skills, build your own)
npm install @omp-workflows/core

# Custom (replace defaultFullstackRoles with your own roster)
npm install @omp-workflows/core
```

```bash
# Or via omp plugin install (resolves the GitHub Packages scope automatically):
omp plugin install @omp-workflows/fullstack
```

```

├── package.json              # workspace root, npm workspaces
├── packages/
│   ├── core/                 # @omp-workflows/core          (public)
│   │   ├── src/
│   │   │   ├── engine/       # state, profile, stage, classify, scope, config, dod
│   │   │   ├── gates/        # classification, monotonic, dod-backstop, safety
│   │   │   ├── commands/     # team, pulse, team-next, team-yolo, init-team, ...
│   │   │   ├── runtime-config.ts
│   │   │   └── index.ts      # public API: registerTeamWorkflow(pi, opts)
│   │   ├── workflows/        # 8 declarative JSON profiles + schemas
│   │   ├── test/             # smoke + integration tests
│   │   └── package.json
│   ├── content/              # @omp-workflows/content       (private, source of truth)
│   │   ├── agents/           # 17 agent markdown files
│   │   └── skills/           # 31 domain skill folders
│   └── fullstack/            # @omp-workflows/fullstack     (public)
│       ├── src/
│       │   └── index.ts      # default export: registerTeamWorkflow with fullstack defaults
│       ├── scripts/
│       │   └── sync-content.mjs   # prepack + postpack: copy content/ → fullstack/ before publish
│       └── package.json      # agents/ + skills/ regenerated by prepack; gitignored
└── .github/workflows/
    └── release.yml           # tag-driven release to GitHub Packages
```

## Usage

```bash
/team Add OAuth authentication with Google and GitHub
/team Fix the 500 error on /api/users endpoint
/team Review my auth changes
/pulse
/init-team
/team-yolo
```

## How it works

`/team <task>` walks:

1. **Classify** the request → `Classification = {type, complexity, confidence, workflow}`.
2. **Resolve** the profile via the `Type × Complexity → Workflow` table.
3. **Write** `.work-state/team-state.json` BEFORE any subagent launch (the gate blocks otherwise).
4. **Walk** stages in profile order. Each by `type`:
   - `orchestrator` → inline orientation
   - `single` → one `task` call
   - `consilium` → parallel `task` calls in one batch
   - `bash` → deterministic shell step
   - `none` → skip
5. **Honour** `consumes`/`produces` typed artifacts.
6. **Honour** `gate` (block `done` until gate holds) and `checkpoint` (interactive: stop; autonomous: apply `autonomous` decision).
7. **Loop** if `loop: { back_to, until, max_iterations }` is set.
8. **Mirror** progress into `team-state.md`.

Gates run as `before_agent_start` (classification + monotonic), `session_stop` (DoD backstop), and `tool_call` (safety). Workflow data is the same JSON files as the legacy `claude-plugin` (v3.0.x). The interpreter moves from markdown prose into TypeScript.

## Release

Releases are driven by pushing a semver tag (`v0.2.0`, `v0.2.0-rc.1`):

```bash
git tag v0.2.0
git push origin v0.2.0
```

`.github/workflows/release.yml` then:

1. Runs `npm ci`, full monorepo build, typecheck, tests.
2. Stamps `packages/{core,fullstack}/package.json#version` from the tag.
3. Runs `npm run sync-content` in fullstack to copy `packages/content/{agents,skills}` into `packages/fullstack/`.
4. Publishes `@omp-workflows/core` then `@omp-workflows/fullstack` to `npm.pkg.github.com` with provenance. `GITHUB_TOKEN` is sufficient (the org's `AndVl1/omp-workflows` repo is public; packages are public).
5. Restores `packages/fullstack/{agents,skills}` to empty via `sync-content --restore`.

## Custom bundles

```typescript
// your-package/src/index.ts
import type { ExtensionAPI } from "@oh-my-pi/pi-coding-agent";
import { registerTeamWorkflow } from "@omp-workflows/core";

const MY_ROLES = {
  architect: "my-architect",
  backend: "my-go-backend",
  tester: "my-qa",
};

export default function (pi: ExtensionAPI) {
  registerTeamWorkflow(pi, {
    label: "my-team",
    roles: MY_ROLES,
  });
}
```

## Migration from `claude-plugin`

Same data (JSON profiles, typed artifacts, agent names, skill names) — same `.work-state/` files. The interpretive prose (`commands/team.md`, 830 lines) is now TypeScript in `core/src/`. The bash hooks (`validate-state.sh`, `dod-gate.sh`, `safety-guard.sh`) are now event handlers in `core/src/gates/`. Documented in `vibe-report/omp-workflows-migration-2026-07-31.md`.

Note: `@omp-workflows/content` is the only canonical place for agent + skill markdown in this repository. The sibling `claude-plugin` repo carries its own copy of the same files; sync between them is currently manual (see `claude-plugin/vibe-report/`).
